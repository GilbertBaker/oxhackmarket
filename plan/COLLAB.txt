5. UNITS AND DOMAIN RULES (everyone must agree)
--------------------------------------------------------------------------------
  - Money: integer PENCE everywhere (DB, API, engine). £1,000 = 100000.
  - New user starting cash: 100000 (£1,000 play money).
  - House bot user: username "house", is_bot=true, cash 100000000.
  - Each market has ONE order book for YES shares. Price = integer 1..99 pence,
    which equals the implied probability in %.
  - A YES share pays 100p if the market resolves YES, 0p if NO.
  - "NO" is a view on the YES book:
        Buy  NO  @ p   ==  Sell YES @ (100 - p)
        Sell NO  @ p   ==  Buy  YES @ (100 - p)
    The DB, engine and internal code store everything in YES terms
    (side 'buy'|'sell' on YES, price in YES pence).
  - Positions are SIGNED YES share counts. Negative = short YES = long NO.
    Per market, sum of all users' positions is always 0.
  - RACES (Union elections): a race = one position in one election, e.g.
    election "Michaelmas 2026", position "President", seats 1.
    Each CANDIDATE in a race is its own binary market: "Will <candidate> be
    elected <position> (Michaelmas 2026)?". It has its own YES book in the
    engine, so the engine needs no multi-outcome support.
    Include "RON (Re-Open Nominations)" as a candidate in every race. It's a
    real option on Union ballots.
    Across a race, candidate prices should sum to about 100 * seats (an
    over/under "overround" is shown in the UI, and the MM bot normalises its
    fair values to that total).
    A race resolves with a list of winning market ids (length = seats).
    Winners resolve YES, every other candidate resolves NO.
    Multi-seat committees: seats = number of places, and each candidate
    market pays if that candidate wins any seat.
    All candidate markets in a race share the race's closes_at (when polls
    close) and its status. Status changes are applied to the race and all its
    markets together.
  - Candidates are students standing in a PUBLIC election, so naming them is
    fine. Markets are ONLY about the election outcome: never allegations,
    misconduct, personal life, or electoral-malpractice rumours about
    individuals.
  - Trades execute at the RESTING (maker) order's price.
  - Current market probability ("price" in the API), computed by B:
        1. latest price_tick with both best_bid and best_ask -> round((bid+ask)/2)
        2. else last trade price
        3. else markets.ai_prior
        4. else 50
  - Equity (leaderboard, portfolio):
        equity = cash + SUM over markets(position_qty * current_price)
    (Short positions contribute negatively. Resolved markets contribute 0
    because positions are zeroed at settlement.)
  - Market (and race) status lifecycle:
        proposed -> open -> closed -> resolved
        proposed -> rejected
    'proposed' = suggested by Gemini, awaiting admin (approval is per race).
    'open'     = tradable (engine book exists).
    'closed'   = past closes_at or closed by admin. No trading, awaiting resolution.
    'resolved' = outcome set, payouts done.
  - Timestamps: stored as timestamptz. Sent over the API as ISO 8601 UTC
    strings with 'Z', e.g. "2026-10-24T14:05:00Z".

6. DATABASE SCHEMA (schema `oxmarket`, written by B in server/schema.sql)
--------------------------------------------------------------------------------
Column lists are the contract. B writes the actual DDL (idempotent:
CREATE ... IF NOT EXISTS). Types are Postgres types.

users
  id serial PK | username text UNIQUE NOT NULL | pw_hash text NOT NULL
  cash bigint NOT NULL default 100000 | is_admin bool default false
  is_bot bool default false | created_at timestamptz default now()

articles
  id serial PK | source text NOT NULL   -- 'cherwell'|'oxstu'|'isis'|'union'
  url text UNIQUE NOT NULL | title text NOT NULL | summary text
  published_at timestamptz | scraped_at timestamptz default now()
  processed bool default false   -- true once Gemini has looked at it

races
  id serial PK | election text NOT NULL   -- e.g. 'Michaelmas 2026'
  position text NOT NULL   -- e.g. 'President', 'Standing Committee'
  seats int NOT NULL default 1 | description text
  resolution_criteria text NOT NULL   -- e.g. 'Official results announced by the Oxford Union / reported by Cherwell'
  closes_at timestamptz NOT NULL      -- polls close
  status text NOT NULL default 'proposed'   -- same lifecycle as markets
  source_name text | source_url text | article_id int NULL -> articles.id
  ai_reason text NULL | created_by_ai bool default false
  created_at timestamptz default now() | resolved_at timestamptz NULL
  UNIQUE (election, position)

markets   (one per candidate)
  id serial PK | race_id int NOT NULL -> races.id | candidate text NOT NULL
  question text NOT NULL   -- "Will <candidate> be elected <position> (<election>)?"
  description text
  resolution_criteria text NOT NULL | category text default 'union'
  source_name text | source_url text | article_id int NULL -> articles.id
  closes_at timestamptz NOT NULL   -- copied from the race
  status text NOT NULL default 'proposed'  -- see section 5, kept in sync with race
  outcome text NULL   -- 'YES'|'NO'
  ai_prior int NULL   -- 1..99, Gemini's initial probability for this candidate
  ai_reason text NULL | created_by_ai bool default false
  created_at timestamptz default now() | resolved_at timestamptz NULL
  UNIQUE (race_id, candidate)

orders
  id bigint PK   -- allocated from sequence oxmarket.orders_id_seq via
                 -- db.next_order_id(), and ALSO used as the engine order id
  market_id int NOT NULL | user_id int NOT NULL
  side text NOT NULL   -- 'buy'|'sell' (YES terms)
  price int NOT NULL   -- 1..99 YES terms
  qty int NOT NULL | qty_remaining int NOT NULL
  status text NOT NULL   -- 'open'|'filled'|'cancelled'
  created_at timestamptz default now() | updated_at timestamptz default now()

positions
  user_id int | market_id int | qty int NOT NULL default 0 (signed YES)
  net_cost bigint NOT NULL default 0   -- pence paid minus pence received
  PRIMARY KEY (user_id, market_id)

trades                        HYPERTABLE on time
  time timestamptz NOT NULL default now() | market_id int NOT NULL
  price int NOT NULL | qty int NOT NULL
  buyer_id int NOT NULL | seller_id int NOT NULL
  taker_side text NOT NULL   -- 'buy'|'sell'
  maker_order_id bigint | taker_order_id bigint NULL (NULL for market orders)
  index (market_id, time DESC)

price_ticks                   HYPERTABLE on time
  time timestamptz NOT NULL default now() | market_id int NOT NULL
  best_bid int NULL | best_ask int NULL | last_price int NULL
  index (market_id, time DESC)

portfolio_snapshots           HYPERTABLE on time
  time timestamptz NOT NULL default now() | user_id int NOT NULL
  cash bigint NOT NULL | equity bigint NOT NULL

ai_briefs
  id serial PK | race_id int NULL | market_id int NULL
                 (briefs + resolution suggestions are per RACE; both NULL = daily digest)
  kind text NOT NULL   -- 'brief'|'resolution'|'digest'
  suggested_winner_ids int[] NULL   -- for kind 'resolution'
  text text NOT NULL | suggested_outcome text NULL | evidence_url text NULL
  confidence int NULL (0..100) | created_at timestamptz default now()

Continuous aggregates (B):
  candles_5m, candles_1h on trades:
    bucket, market_id, open, high, low, close, volume
    (time_bucket + first(price,time)/max/min/last(price,time)/sum(qty))
  with refresh policies. Compression policy on price_ticks (> 1 day).

8. ENGINE PROTOCOL (A implements in C++ MarketServer; A uses it from engine.py)
--------------------------------------------------------------------------------
  Process: ENGINE_PATH, started by engine.py. Text over stdin/stdout, one
  command per line, ASCII, space-separated. On start it prints "READY".
  Every response is zero or more lines followed by a line "END".
  On error: "ERR <reason>" then "END".
  trader id = users.id. order id = orders.id (allocated by Python).

  PING                                          -> PONG / END
  NEW <mkt>                                     -> OK / END   (idempotent)
  LIMIT <mkt> <orderId> <traderId> <B|S> <price> <qty>
        -> FILL <makerOrderId> <makerTraderId> <price> <qty>   (0..n lines)
           RESTING <qtyLeftOnBook>                             (0 if fully filled)
           END
  MARKET <mkt> <traderId> <B|S> <qty>
        -> FILL ... (0..n lines) / UNFILLED <qty> / END
  CANCEL <mkt> <orderId>                        -> OK / END  or  ERR not_found / END
  BOOK <mkt> <depth>
        -> BID <price> <totalQty>  (best first, up to depth)
           ASK <price> <totalQty>  (best first, up to depth)
           END
  QUIT                                          -> process exits

  Example:
    > LIMIT 3 1042 7 B 60 100
    < FILL 1031 1 58 40
    < FILL 1033 1 59 20
    < RESTING 40
    < END
