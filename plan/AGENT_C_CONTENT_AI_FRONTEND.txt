CURRENT SCOPE: OXFORD UNION ELECTIONS ONLY
  Markets are "who wins each position" in Oxford Union elections (President,
  Librarian, Treasurer, Secretary, Standing Committee, Secretary's Committee,
  ...). A RACE = one position in one election. Each candidate in a race is a
  binary market. Every race also gets a "RON (Re-Open Nominations)"
  candidate. Read COLLAB 5 "RACES" carefully. Cuppers, sport and general news
  are OUT of scope. Ignore those articles.

   races + candidates from articles, explain how races have moved, and
   detect results for resolution.

The GEMINI_API_KEY arrives LATER. Everything must work with FAKE_AI=1 first.

C2. server/scraper.py
  - SOURCES = list of {name, source_key ('cherwell'|'oxstu'|'isis'|'union'),
    feed_url, fallback_url, selectors}.
  - Relevance filter BEFORE insert (keeps the DB on-topic): keep an item
    only if title or summary matches Union-election keywords
    (case-insensitive): "Oxford Union", "Union election", "President-elect",
    "Librarian", "Treasurer", "Standing Committee", "Secretary's Committee",
    "hustings", "slate", "RON", "re-open nominations", "candidates", "OxUnion".
    Plain "Union" alone is too broad (e.g. Student Union / SU elections are
    a DIFFERENT body), so require "Oxford Union" or an election-position
    keyword together with "Union". Items from source 'union' are always kept.
  - scrape_all() -> int: for each source, fetch with requests (timeout 15 s,
    User-Agent "OxMarket-OxHack/1.0 (student hackathon project)"), parse
    with feedparser (BeautifulSoup fallback), normalise to {source, url,
    title, summary (plain text, max ~800 chars, strip HTML), published_at
    (UTC)}, filter, then db.insert_article (dup url -> skipped). One failing
    source never stops the others. Log counts per source (fetched / kept).
  - Store only headline, short summary and link. Never copy full articles.
    You MAY fetch the full article page transiently to give Gemini the
    candidate list (candidate names are often only in the body). Never
    store or display the body text.
  - Test with saved sample feed XML/HTML in server/tests/fixtures/ (no
    network in unit tests), including a Student Union article that must be
    filtered OUT.

C3. server/ai.py (Gemini, signatures fixed in COLLAB 7.3)
  - SDK: google-genai (from google import genai; client =
    genai.Client(api_key=...)). Model from GEMINI_MODEL. When the key
    arrives, confirm the current recommended flash model name and update
    .env.example if needed.
  - FAKE_AI=1 (or no key): deterministic canned outputs so the whole
    pipeline runs offline. E.g. extract_races returns, for any article whose
    title contains "Union", one race {election "Michaelmas 2026", position
    "President", seats 1, closes_at = the next polling day, candidates
    "Fake Candidate 1/2/3" priors 40/35/20}. detect_result returns winners
    [] (unclear) unless the article title contains "elected". Every function
    supports fake mode.
  - Use structured JSON output (response_mime_type="application/json" plus
    a response_schema) for extract_races and detect_result. Validate in
    Python: position non-empty; seats 1..10; 2..12 candidates with unique
    non-empty names; priors 1..99; closes_at in the future and within 4
    months; election matches "(Michaelmas|Hilary|Trinity) YYYY". Drop
    invalid races. Return [] / empty winners on anything invalid.
  - extract_races(article, body_text=None) prompt requirements:
      * Extract ONLY Oxford Union (the debating society) elections. Ignore
        the Oxford SU / college JCR elections and everything else.
      * Each race: election term, exact position title, seats (e.g.
        Standing Committee has several), the confirmed candidates named in
        the text (no guessing, and no people merely rumoured), polling
        date/time if stated (else null, and content.py uses the known
        polling day from C1).
      * Exclude "RON". content.py always adds it.
      * prior per candidate = honest win probability (sum ~100*seats)
        using only signals in the text (incumbency/slates/endorsements/
        uncontested), plus a one-line reason. If no signal, use equal priors.
      * Never output allegations, misconduct, personal details or anything
        beyond name + position. Names exactly as printed.
      * Include today's date (UTC) in the prompt.
      * Return [] for articles that are about the Union but contain no
        election race (e.g. a speaker event).
  - race_brief(race, candidates_history, articles): input = race position,
    each candidate's hourly price series (last 24-72h from
    db.race_history), volumes, recent related articles. Output: 2-4
    sentences, "who's leading, who moved and the likely reason (cite which
    article)", no invented facts, neutral tone about candidates. If nothing
    moved, say so.
  - detect_result(race, articles): give the race, candidate names and
    articles published after the race's created_at. Output the COLLAB 7.3
    dict. Winners must be names from the candidate list (or "RON"). Return
    empty winners when the result isn't stated explicitly.
  - daily_digest(races): a short "Union election odds today" paragraph:
    favourites per position and biggest movers.
  - Rate limiting/cost: one call at a time (lock), at most N articles per
    scrape run (env AI_MAX_PROPOSALS, default 10), retry once on transient
    errors, log every call (prompt kind, latency, success).
  - Save each prompt template as a constant at the top of ai.py (the write-up
    will quote them).

C4. server/content.py
  - process_new_articles(): scraper.scrape_all(), then for each
    db.unprocessed_articles(): races = ai.extract_races(article, body). For
    each race:
      existing = db.find_race(election, position)
      none   -> db.create_race({status 'proposed', created_by_ai True,
                ai_reason, article_id, source_name, source_url, ...}), then
                one db.create_market per candidate (question "Will <name> be
                elected <position> (<election>)?", ai_prior, status
                'proposed', closes_at = race closes_at, category 'union')
                plus a RON market (prior = whatever is left so the total is
                ~100*seats, min 3).
      proposed -> add newly named candidates as extra proposed markets.
      open     -> do NOT add automatically. Log it and include the new
                  names in the race's ai_reason so the admin sees "new
                  candidates mentioned: X" (the admin adds them via the
                  add-candidate endpoint).
      closed   -> run ai.detect_result on the article and save_brief(kind
                  'resolution', suggested_winner_ids, confidence,
                  evidence_url). NEVER auto-resolve. The admin confirms.
    Always mark_article_processed. Returns the number of races
    created/updated.
  - start_background() (unless DISABLE_JOBS=1): daemon threads for
    process_new_articles every 30 min (first run 30 s after start), brief
    refresh every 30 min for open races where any candidate moved >= 5
    points in 24h, daily digest every 24 h (also at start if none exists
    today). Every loop has try/except + logging.
  - refresh_brief(race_id) -> dict, used by the loop and the refresh
    endpoint: gathers inputs, calls ai.race_brief, then db.save_brief(kind
    'brief', race_id).

C5. server/content_api.py (Flask blueprint `bp`)
  Endpoints exactly as COLLAB 9 "Content & AI [C]": articles, race brief,
  brief refresh (rate-limited to 1 per 10 min per race, checked via
  latest_brief created_at), digest, admin proposed / create race / approve
  / reject / add candidate / scrape / suggest-result.
  - Create race (manual): validates like extract_races, creates race +
    candidate markets + RON, status 'open', then trading.open_race.
  - Approve: apply edits (if "candidates" is given, replace the proposed
    candidate markets with that list + RON), then db.update_race(status
    'open') (propagates to markets), then trading.open_race(id).
  - Reject: db.update_race(status 'rejected').
  - Add candidate: create_market in the race (same status as the race). If
    the race is open, trading.open_market(id).
  - Suggest result: ai.detect_result on articles since the race was created.
    Map names to market ids, save_brief(kind 'resolution'), return the
    COLLAB shape. Resolution itself is A's endpoint (the admin UI calls it).
  Admin check: your own helper or B's admin_required. Errors: 400/403/404
  {"error"}.
