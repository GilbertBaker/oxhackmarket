BACKGROUND: THE EXISTING ENGINE (read the code before changing anything)
--------------------------------------------------------------------------------
  book/OrderBook/
    Order.h/.cpp                      Order(price, qty, time, traderID, orderID, buyOrder)
    DataStructures/OrderBook.*        placeBuyOrder/placeSellOrder (limit),
                                      placeBuyInstantOrder/placeSellInstantOrder (market),
                                      cancelOrder, deleteOrder, getBestBid/Ask,
                                      outputOrderBook (console only)
    DataStructures/OrderTree.*        AVL tree of price levels, has
                                      printLowestLevels/printHighestLevels
    DataStructures/OrderList.*, OrdListNode.*   FIFO list per price level
    Traders/Trader.*, TraderAlgo.*    trader accounts + random-bot simulation
    OrderBookTests.cpp, OrderBookBenchmark.cpp, main.cpp, CMakeLists.txt
  Facts that matter:
  - Trades execute at the resting order's price, with price-time priority.
  - The engine moves Trader money/qOwned itself. We IGNORE those engine-side
    balances. Python/Postgres is the source of truth.
  - TraderAlgo::getTrader(id) does traders[id], which returns nullptr for an
    unknown id. That crashes in OrderBook as soon as a web user trades.
  - TraderAlgo's constructor creates 100 random traders. getNextID() is per
    TraderAlgo, so ids would collide across markets. That's why Python
    allocates order ids (COLLAB 8).
  - No way to observe fills or read depth programmatically.
  The owner wrote this engine to learn. Respect the style (naming, comments,
  formatting), keep changes minimal, and DO NOT rewrite the matching logic,
  the AVL tree or the lists.

A5. server/risk.py
  Pure functions with no DB access, so they're easy to unit test. Inputs are
  plain dicts/lists from db:
  - locked_cash(positions, open_orders) =
        SUM over markets 100 * max(0, -position_qty)
      + SUM open buy orders  price * qty_remaining
      + SUM open sell orders (100 - price) * uncovered_qty
    where, per market, uncovered_qty for sell orders = the part of the total
    open sell quantity NOT covered by max(0, position_qty).
  - available(cash, positions, open_orders) = cash - locked_cash(...)
  - check_order(cash, positions, open_orders, market_id, side, price, qty)
    -> None or raises RiskError("Insufficient funds: need X, available Y")
    by computing available before and after adding the hypothetical order.
  - worst_case_market_cost(book_side_levels, qty) -> (cost, fillable_qty)
    for market orders. Buying walks the asks (cost = sum price*qty). Selling
    walks the bids (cost = collateral (100-price) per uncovered share).
  Unit tests: long covering a sell needs no collateral; a naked short needs
  (100-p); a buy needs p*q; a mixed case.

A6. server/trading.py (service layer, signatures fixed in COLLAB 7.1)
  - place_order:
      1. Validate: market exists and status=='open'; outcome/side/type valid;
         1<=price<=99 for limit orders; 1<=qty<=100000.
      2. Map to YES terms (COLLAB 5): NO buy p -> YES sell (100-p), NO sell
         p -> YES buy (100-p).
      3. Under the engine lock (hold it for steps 3-6 so trades are strictly
         ordered): load cash, positions and open orders and run the risk check.
         Market orders: read book depth, use worst_case_market_cost, and cap
         qty at what's affordable and fillable. If 0, raise TradingError
         "No liquidity" or "Insufficient funds".
      4. Limit: order_id = db.next_order_id(); engine.limit(...).
         Market: engine.market(...).
      5. In ONE db.transaction(): for each fill, buyer/seller = taker or maker
         by side; adjust_cash buyer -p*q and seller +p*q; add_position buyer
         +q (cost +p*q) and seller -q (cost -p*q); update_order for the maker
         (qty_remaining -= q, status 'filled' at 0); insert_trade. Then
         insert_order for the taker limit order (status 'open' if resting>0
         else 'filled'; qty_remaining = resting). If any fills happened:
         record_tick(market, best_bid, best_ask, last fill price) using a
         fresh engine.book(mkt, 1).
      6. Return {"order": Order or None, "fills": [...]}.
    Self-trades are allowed (they net out). The MM bot avoids them by
    cancelling its own quotes before requoting.
    If the DB transaction fails after the engine has matched, log at ERROR
    and restart the engine plus replay from DB, which brings the engine back
    in line with the DB.
  - cancel_order: owner (or admin) check, the order must be 'open',
    engine.cancel, update_order(status='cancelled').
  - close_market: cancel every open order in the market (engine + DB), then
    db.update_market(id, status='closed'). Idempotent.
  - resolve_market: market must be 'open' or 'closed'. close_market first.
    In one transaction: for each position, if outcome YES adjust_cash
    (user, 100*qty) (negative qty pays). Then set every position qty to 0
    (add_position with -qty, cost delta 0) and update_market(status=
    'resolved', outcome, resolved_at=now). Log the totals paid.
  - open_race: open_market for every candidate market in db.race_markets.
  - close_race: close_market for each candidate, then db.update_race(id,
    status='closed'). Idempotent.
  - resolve_race(race_id, winner_market_ids): validate that every id belongs
    to the race, len == seats (or exactly [RON market] if RON wins), and the
    race is open/closed. close_race first, then resolve_market YES for
    winners and NO for everyone else. Then db.update_race(status='resolved',
    resolved_at=now). Do it all in ONE db transaction (pass conn through,
    so a failure leaves nothing half-paid).
  - get_book, available_cash, open_market, startup (replay, COLLAB 7.1),
    start_background (starts mm_bot unless DISABLE_JOBS=1).
  Done when: tests with a fake db (in-memory dict implementing the db
  functions you use) and the real engine cover the scenarios in VERIFICATION.

A8. server/mm_bot.py (house market maker)
  - Every 10 s (daemon thread, started by trading.start_background), for each
    race with status 'open', for each of its candidate markets:
      raw = blend: if there are no trades yet, raw = ai_prior or
            (100*seats / number of candidates); else raw = EMA(alpha 0.3)
            of recent trade prices, pulled 10% toward ai_prior. Keep state
            in memory per market.
      Normalise across the race: fair_i = raw_i * (100*seats) / sum(raw),
      then clamp to 2..98. (Probabilities within a race must be
      consistent. Without this the bot would quote President candidates
      summing to e.g. 140%.)
      skew = clamp(-house_position / 50, -3, 3) points
      bid = clamp(round(fair + skew) - 2, 1, 98), ask = clamp(round(fair +
      skew) + 2, 2, 99), and ask > bid always.
      Cancel the house's previous open orders in that market, then place a
      limit buy (bid, 50) and a limit sell (ask, 50) via trading.place_order
      as the house user (db.ensure_bot_user()). The bot can short. Its huge
      cash covers collateral.
  - Each market is wrapped in try/except, and errors are logged.
  - Expose requote_all() for tests and for an admin "kick" if useful.
  Done when: within 15 s of the app starting, every open market shows a
  2-sided book on /api/markets/<id>/book.
